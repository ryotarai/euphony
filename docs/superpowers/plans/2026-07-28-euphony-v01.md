# Euphony v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify a single-binary, token-authenticated web terminal with multiple PTY sessions and responsive desktop/mobile navigation.

**Architecture:** A Go HTTP server owns PTY processes, session metadata, one-time WebSocket tickets, and embedded frontend assets. A Vite React client calls the JSON API, renders terminal streams with xterm.js, and adapts session navigation between a desktop rail and mobile drawer.

**Tech Stack:** Go 1.24, `github.com/creack/pty`, `github.com/coder/websocket`, TypeScript 5, React 19, Vite 7, Vitest, Testing Library, xterm.js

## Global Constraints

- Require `EUPHONY_TOKEN`; never place the long-lived token in a WebSocket URL.
- Store the browser token only in `sessionStorage`.
- Keep session state in memory; do not add persistence or split panes.
- Serve the production frontend from the Go binary with `go:embed`.
- Use English for code, documentation, logs, and UI copy.
- Support current desktop and mobile browsers with keyboard-accessible controls.
