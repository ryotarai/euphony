# Agents Action Priority and Done Workflow

## Goal

Make the Agents pane a focused action queue: AI-generated action priorities make the queue scannable, unread state stays visible without a second mailbox tab, and a human can explicitly complete an action and move it to a Done tab.

## Current context

Agent summaries are generated by the existing command-line summary service and persisted in `agent_summaries`. A summary has a status, summary text, optional action text, generated timestamp, unread state, and provider error. The web pane currently splits summaries into Unread and Read tabs while retaining Action required and Running sections inside each tab.

## Design

### Summary contract

`AgentSummary` gains two persisted fields:

- `priority`: `high`, `medium`, or `low`. The field is returned for waiting and blocked actions and is omitted/empty for running summaries. Older rows without a priority remain readable and render as Medium until the next AI generation.
- `done`: a boolean that identifies an action explicitly completed by the user. New summaries and action changes set it to false.

The AI prompt asks for exactly one JSON object with `summary`, `action`, and `priority`. Running agents must return an empty action and empty priority. Waiting and blocked agents must return a concrete action and one valid priority. The parser rejects missing or invalid priority for those statuses, so the UI never treats arbitrary model text as a priority.

Priority is deliberately about the action, not the lifecycle status. The web pane sorts Action required cards by High, Medium, then Low; ties use newest `generatedAt` first and then terminal ID for deterministic rendering. Running cards remain in their own section and do not receive an action priority badge.

### Done and unread transitions

The session manager remains the source of truth for both flags:

| Event | `unread` | `done` |
| --- | --- | --- |
| First summary for a terminal | `true` | `false` |
| Same action text regenerated | preserve | preserve |
| Trimmed action text changes | `true` | `false` |
| User opens the card | `false` through the existing read endpoint | preserve |
| User presses the checkmark | `false` | `true` |

Action comparison trims surrounding whitespace. A changed action reopens the item even when its previous action was Done. A priority-only change does not reopen an item because the actionable instruction is unchanged. Summary/status refreshes preserve the flags unless the action text changes.

The server exposes `POST /api/agent-summaries/{id}/done`, persists the transition, and publishes the normalized `agent.summary.updated` event. The existing read endpoint remains available for opening cards. Both transitions are idempotent and return the normalized summary.

### Agents pane interaction

The two mailbox tabs become:

- `Action required`: waiting and blocked summaries that are not Done, followed by running summaries that are not Done.
- `Done`: summaries explicitly marked Done, sorted newest first within their priority groups.

There is no Read tab. Unread summaries use the existing quiet amber palette but communicate unread state primarily through bold title, summary, and action text, matching Gmail's low-noise convention. Read text uses the normal weight. The card header retains status and provider metadata.

Action cards show a compact `High`, `Medium`, or `Low` badge next to the action label. The badge uses one semantic color per level, includes a text label for accessibility, and does not rely on color alone. Each not-Done action card has a separate checkmark button. Pressing it marks the summary Done without opening the terminal, updates local state from the API response, and selects the Done tab so the moved card is immediately visible. Opening the card body still marks it read and opens the linked terminal. A failed Done request leaves the card in place and shows the existing Agents error region.

### Data flow and race handling

The existing App summary revision and snapshot merge logic remains in place. The new Done response uses the same revision bump and snapshot guard as the read response, so a stale request cannot overwrite a newer AI-generated action. The existing `agent.summary.updated` event replaces the summary by terminal ID; when that event carries a changed action, the server-normalized `done: false` and `unread: true` move the item back into Action required automatically.

### Visual direction

Keep the near-black terminal-first workspace and current monospace metadata. The signature element is a quiet priority ladder: a text badge with a colored edge that lets a human scan urgency without turning every card into a warning. Remove the unread dot and mailbox-style split so the card's typographic weight carries unread state. Keep separators flush between cards, visible keyboard focus, responsive wrapping, and reduced-motion behavior.

## Testing strategy

- Go unit tests cover prompt instructions, generation parsing, priority propagation, manager Done/read/action-change transitions, SQLite migration and persistence, and the protected Done endpoint/event.
- Vitest covers API encoding, priority sorting, badge labels, absence of the Read tab, unread typography hooks, Done-tab movement, checkmark keyboard activation, and failed requests.
- App tests cover Done response replacement, stale summary protection, and event-driven reopening after an action change.
- Playwright exercises the rendered Agents pane with deterministic API responses and verifies the checkmark flow without invoking an external AI provider.

## Non-goals

No manual priority editor, bulk Done action, per-user state, new provider, or separate unread counter system is introduced.
