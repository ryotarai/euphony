# No-Authentication Mode Design

## Goal

Allow a local Euphony instance to run without an access token when the operator
explicitly sets `EUPHONY_AUTH_MODE=none`, while preserving token authentication
by default.

## Behavior

- `EUPHONY_AUTH_MODE` accepts `token` (default) or `none`.
- An unknown value is a startup error so a typo cannot silently disable
  authentication.
- In `token` mode, the existing `EUPHONY_TOKEN` behavior is unchanged: a
  configured token is used as-is and an unset token is generated by the CLI.
- In `none` mode, an empty token is valid, all Euphony API routes are callable
  without `Authorization`, and terminal WebSocket connections continue to use
  the existing short-lived, single-use ticket flow.
- `GET /api/auth/config` is public in both modes and reports the active mode so
  the browser can distinguish a missing token from an intentionally public
  server.
- The browser skips the token form in `none` mode and does not send an empty
  `Authorization` header. A token-mode `401` still clears browser session state
  and returns to the token form.
- Agent hooks keep working in `none` mode by omitting `Authorization` when no
  token is configured. Hook failures remain non-blocking for the agent.

## Security boundary

No-auth mode is an explicit opt-in intended for trusted local environments. The
default remains token-authenticated, and the README must warn that binding a
no-auth server to a non-loopback address exposes terminal control to anyone
who can reach it.

## Implementation

- Add an auth-mode type and conditional middleware wrapping in
  `internal/server/server.go`.
- Add CLI environment parsing in `cmd/euphony/main.go`.
- Make `internal/agenthook.Report` send requests without an authorization
  header when its token is empty.
- Add a small public auth-config request path to `web/src/App.tsx` and make
  `web/src/api.ts` omit auth headers for an empty token.
- Update `scripts/dev.sh` and README usage/documentation.

## Verification

Cover both modes with Go route tests, CLI mode parsing tests, no-token hook
tests, and a React test that bootstraps the workspace without showing the token
form. Run the existing Go, frontend, typecheck, build, and E2E checks.
